# Selected-bot conversational relay

A completed intelligible instruction uses the existing normal Send/steer boundary in the selected bot's native thread. The Operator prompt asks for near-verbatim material details, including recipients/projects, hardware generations, dates/amounts, negations and draft-versus-send. Clear intent does not need optional length/style questions. This is prompt behavior, not a claim that ASR or a voice model cannot omit facts; genuine harmless call acceptance must cover it.

The shared `OperatorVoiceEvents` coordinator is used by browser WebRTC, SIP sideband and Media Streams. It keeps bounded visible native evidence pending while the caller, provider response, tool-output continuation or audio playback occupies attention. Useful questions/results take priority and obsolete commentary is coalesced by exact bot/turn/item. Two call requests sharing native evidence do not manufacture two completions. A confirmed switch changes the current identity; older results retain their original bot/segment attribution. Native receipts, current input bindings and Stop remain authoritative.

Tool outputs retain their original function call IDs and precede the coordinated continuation. Readback responses carry the captured segment/readback metadata and disable tools. Transport writes and generation completion do not prove human hearing or native completion. Successful message generation plus playback settlement acknowledges voice attention only. Interrupted/failed readbacks remain unacknowledged, using original evidence/item/readback identities for bounded retries. An unknown response-create acknowledgement is held until a correlated error or transport reconciliation. After three explicit failed/interrupted response attempts, automatic speech for that unchanged evidence is withheld so newer results can proceed; the original evidence/native receipt remains available through track-work/history. No native action is retried by this coordinator.

WebRTC/SIP use provider output-buffer completion/clear events. Media Streams sends a Twilio mark after audio; only the matching un-cleared mark settles playback. A clear echo is not played audio. Obsolete sockets and ended-call tool completions do not affect a new call or conversation. Hangup/barge-in do not invoke native Stop.

Attention limits: at most 100 pending entries/48,000 UTF-8 bytes, a batch at most three entries/24,000 bytes, 200 compact dedup records/16,000 bytes, 100 completed native groups/8,000 bytes, 100 withheld records/16,000 bytes, and bounded existing item/response aliases. Compact dual hash values are voice-attention dedup only, not authentication or operation fingerprints. Evidence over 12,000 bytes uses a small input-required notice; fresh exact normal question controls supply complete wording/choices, never a truncated answer. Native operation and full call history are retained independently.

SIP persists the optional versioned attention snapshot under `sip-voice-readback-v1`, separately from existing `sip-call` metadata. Hydration checks the original call ID and merges in-flight batch evidence. The original call value retains compatible `voiceSeen` metadata; no D1/schema migration, new credentials or provider/model/voice configuration is required. Older versions ignore the optional key; rollback may repeat voice readbacks, but must not replay native requests or call history. `operator.mjs` projects only visible `agentMessage` commentary/final/legacy-null phases from existing bounded reads and never forwards reasoning/tool bodies.

Rollout spans the existing Sites app/Media Streams worker, the existing voice-relay Wrangler bundle, and the bot bridge's narrow evidence filter. Dwight owns compatible integration, publication and any required strict-idle activation. Keep original calls, queue/reference items, profiles, settings and uncertain IDs; do not copy/replay an earlier business task as a check. A harmless genuine owner browser/phone call remains required for ASR, spoken phrasing, audio timing, SIP reconnect and device acceptance.
