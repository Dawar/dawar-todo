**Focused changes**

- [Transport selection and fallback](../../app/attachment-sync.ts#L83): require a positive capability before choosing direct image processing. Absent capability uses the browser path. Persisted `imageBindingAvailable:false` or prior 503/image-binding evidence also uses the browser path. An explicit multipart 503 with the typed code and phase immediately falls back to browser prepare/upload/finalize with the **same local upload ID**, original Blob, target and draft identity. The unavailable fact survives a later prepare/storage failure, so retry does not repeat known-broken multipart. Generic/auth errors do not trigger this fallback.
- Existing server prepare replay, derivative-key reconciliation, finalizer CAS, cancellation and ready replay remain authoritative. No prepared rows are deleted on ambiguity. A lost success response retains local bytes; the next recovery check acknowledges the existing ready ID without another prepare or storage upload. No new ID, reattachment, or hidden pending row is used to clear the banner.
- [Lease transitions](../../app/offline-store.ts#L790): acquired attempts explicitly enter queued state; a callback resumed after lease expiry cannot renew ownership without a new attempt. Token comparisons still reject a previous owner's writes/acknowledgement. Failure clears both phase and lease. [Shared lease interpretation](../../app/attachment-queue.ts#L8) requires a token and finite expiry, so malformed/ownerless legacy leases cannot indefinitely block explicit retry. Original IDs/bytes and rejected/cancelled intent remain intact; DB stays **v11**, no destructive migration.
- [Status panel](../../app/attachment-queue-panel.tsx#L13): committed rows drive both counts and messages even when the panel is closed. Reads/visibility/online/offline events refresh the clock. A one-shot lease-expiry timer ages counts and Retry eligibility; interrupted rows need attention. Blocked-only queues have no periodic status timer. Error/byte saving/original-file recovery controls and mobile width constraints remain.
- [Attempt evidence](../../app/attachment-sync.ts#L32): privacy-safe events include document build, recovery protocol 2, capability category, fallback reason and lost ownership versus a committed deferral. No names, IDs, payload content, credentials or signed URLs are added. The existing report still exposes persisted transport/phase/status/lease and byte counts.
- SW generation advances **v33 → v34** to deliver the new graph; previous-generation retention and database v11 fencing remain. Manager owns publication. No forced reload, user storage clearing or native restart.
