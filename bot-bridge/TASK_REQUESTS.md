# Protected Task Requests v1

Original `jim-task-requests-20261005-v1`; Jim writes server/native/private contracts, Cody the approved UI. Source implementation only; capability, public publication, installed backend and genuine contributor acceptance are separate. `lib/task-requests.ts` is the canonical validator/DTO/tool schema. No executable components, secret defaults, task CRUD or new approval semantics.

## Owner and guest consumers

All operations are POST JSON. `/api/task-requests/owner` requires the existing genuine signed-in owner. `taskRequestOwner` accepts the action union. `draft/edit/read` return `{request}`; `list` returns newest-created requests, a scoped `before` row cursor for older continuation and `{requests,nextCursor}` (up to40,256KiB). Mutation `operationId` stays original. `edit/publish/revoke.expectedRevision` is **request revision**. Publication freezes it. `publish` alone returns `{request,url}` with a fragment bearer token: `/task-request#<encoded id>/<token>`. The token/PIN are never in D1 operation results. Publication retries regenerate that same link from the original operation.

The guest page reads the fragment into RAM, then removes it from the address bar without adding a history entry. Never put token/PIN/private values/ciphertext in localStorage, IndexedDB, ordinary journals, analytics, error logs or serialized state. Reopening needs the original link. Use a dedicated guest page: do **not** start `BotsClient`, Tasks sync, app-shell screen preloads, push registration/renewal or an owner session as guest fallback. Current root `AppShell` starts `taskSync` on all non-`/open` paths and `PwaRegister` can renew push; these need the Cody-owned guest-route guard. The ordinary PWA navigation fallback must not replace this guest page with an owner Tasks shell when offline. Guest documents contain no server-rendered form answers or token. API responses are private/no-store and the fragment is not an HTTP referrer.

`taskRequestGuest` sends the bearer and optional `X-Task-Request-PIN` only to the fixed same-origin guest API with credentials omitted, no referrer and redirect refusal. The server derives grant/owner/request/revision/bot/thread. It rejects other actions and neighboring files. Contributor name is self-asserted. PIN is4–12digits; lifetime default7days/max30. Guest/IP and per-request minute limits are60; no auth/security-zone change.

`read/save/submit` return `{request}`. `save.expectedRevision` and `submit.expectedRevision` refer to **submission revision**, starting0; `submission.id` is server-issued and remains original. Save only allowlisted ordinary text/choice values. Files/private values are not ordinary values. Submit freezes one ordinary submission plus one durable delivery intent. Do not clear the current draft on errors or an unknown ACK. Retry the same exact operation or read status; never generate another final-submit ID to evade uncertainty. Display `request.submission.status` for delivery, independent of the form's published/revoked status.

Ordinary upload uses `{file,upload?}` from `upload`, existing S3 FormData POST, then `finalize` → `{file}`. The signed upload URL is the only ordinary-byte destination; never send bearer/PIN/cookies to it or follow redirects. Original file ID/SHA256/size/name stays unchanged. Same-ID prepare/finalize recovery is supported. Limits12files/100MiB each and six ordinary PNG/JPEG/WebP images; private fields cannot use this route. `download` returns only this grant's original ready file `{file,url}`. Keep preview URLs scoped and clean them up; preserve unrelated drafts/files.

## Exact source and chronological placement

`taskRequests.source` is owner-browser-only through the existing Bots client. Params `{threadId,turnId,itemId,cursor?}` seed a selected assistant response, with existing bounded reply lookup/continuation; `{threadId,questionKey}` seeds exact ordinary native questions. Response `{source,spec,nextCursor,unavailable}`. Private/authorization questions stay in their original owner UI. Do not infer a replacement source on error or import existing answer drafts automatically.

Native `bots_draft_task_request` authenticates the current named foreground caller, captures original source once and recovers the same original draft. No publication or independent message start. `task-request` event contains request ID/thread/revision; `task-request.private` contains ID/thread/state only. The owner UI reads scoped list on mount/reconnect/event and inserts a compact card using original source and creation time without moving the reading anchor. It must fence owner/bot/thread changes and late reads. No history scan or private reasoning.

## Private submission

`secure-session` requires the published grant and original `submission.id`, returning `TaskRequestSecureSession` (one-time signed ticket valid60s; dedicated connection valid15min). `TaskRequestPrivateClient` authenticates **task-request** role, receives no snapshot/history/RPC/tool/desktop ability. The crypto owner binding is an opaque keyed per-grant alias, not the configured owner email or owner-role identity. Every frame is scoped by the signed ticket and revalidated against current D1 scope at the bridge.

Call `connect`, then `descriptor`, `encrypt` and `transfer`. Supply existing `SecurePayload` with declared fields/images and explicit **unchecked-by-default** `modelRead`. Keep original envelope in component RAM after an unknown acknowledgement; on reconnect obtain a fresh scoped connection but reuse that envelope/submission/handle. Status may inspect the original handle. A received envelope cannot be changed or decrypted a second time. Clear client private references and temporary URLs/buffers on confirmed completion/close/expiry; a successful Submit must keep the server handle available for the originating bot until use/expiry, while explicit cancellation may delete it; do not auto-create a replacement.

The bridge records only an opaque positive receipt (`handle/submissionId/expiresAt/modelRead`) in D1; no values, images, ciphertext or keys. Final Submit requires that positive receipt and exact handle. It does not trust a claimed receipt. The bridge independently checks live RAM/purpose/destination/binding before the one combined handoff and again at actual queued native admission. Revocation or expiry retains ordinary data as Needs review/Private unavailable. A restart cannot recover secrets. Existing model/history copies, if explicitly permitted, keep their existing consent limitations. Bound private forms are excluded from ordinary owner-only secure cards and never cause a separate secure-receipt wake.

## Native delivery and limits

Standalone submissions use the existing original-ID foreground inbox and queue admission, never steer active work, bypass Stop/maintenance or create a Goal/task/approval. Native queue acknowledgement is `native-accepted` with original queue ID; an eventual turn ID is evidence, not assumed. Unknown input remains uncertain and is reconciled by existing native receipt recovery without another effect.

A linked normal question is revalidated under the existing answer lock against exact bot/thread/turn/key/hash/fields. Ordinary strings/choices use the normal answer adapter, with each native string explicitly labelled as contributor data (not owner approval), original request/submission IDs and self-asserted contributor. Literal selected values remain unchanged in the durable submission; native receives those values inside the attributed string, with no new native schema. Replaced/resolved/private/authorization questions and questions with files/private handles retain contributed data as Needs review; the existing native answer string contract cannot safely accept these attachments. No generic queued answer fallback. A sync response write is `response-sent`; an async positive receipt is `native-accepted`; a missing post-send ACK is Uncertain and never automatically repeated.

D1 tables are additive and lazily ensured as in existing BotStorage, with original operation/CAS guards. Delivery pages rotate bounded cursors (four at most) so older waits cannot starve later submissions. Maintenance counts active TaskRequest transport/work/unknown effects and all existing secure RAM. The fixed historical manager refusal classifier is rebound only after exact original twelve-record and four unchanged-producer-guard verification; no old worker replay.

Rollback is Jim's exact commit revert plus capability-gated UI withdrawal before Dwight's compatible backend cutover. Preserve all new durable rows/submissions/uncertainty and existing ordinary files; never drop tables or replay delivery. Real protected-link submission with harmless ordinary/private data and iPhone/PWA checks remains required before full live acceptance.
